# OI Notebook 知识库与训练沉淀中心升级 PRD

> 版本：v0.1  
> 适用范围：OI Notebook 下一轮产品升级讨论与开发拆解  
> 核心约束：本轮先不接入新 AI 能力；AI 相关位置、数据结构、交互入口需要预留，等待 AI 系统同步升级完成后再对接。

---

## 1. 背景与问题

当前 OI Notebook 已经具备 Markdown 笔记、frontmatter 管理、本地博客、洛谷导入中心、NoteX 等能力。但现有内容组织方式仍然偏向“题解文章管理”：用户通过洛谷导入中心扫描提交记录，再把代码后的大段注释整理成一篇 Markdown 题解。

这种模式存在几个明显问题：

1. **OI 知识并不总是适合写成长文。** 竞赛学习中大量有效知识是短小的 trick、坑点、模板细节、算法识别信号、思维转化方式。强行写成完整题解会显得空、重、维护成本高。
2. **当前内容之间缺少关联。** 题目、算法、trick、错因、专题、比赛复盘之间没有自然建立关系，用户积累越多，越容易变成孤立 Markdown 文件。
3. **洛谷导入中心定位偏窄。** 它现在更像“提交记录搬运器”，而不是“训练成果沉淀入口”。
4. **复习场景不够突出。** 用户考前或阶段性回顾时，更需要快速看到最近积累了哪些知识点、哪些 trick 反复出现、哪些错因高频，而不是逐篇打开长题解。
5. **努力缺少可视化反馈。** 用户持续写题解和训练复盘后，需要看到自己的知识网络正在增长，这能增强继续使用软件的动力。

因此，本轮升级的核心目标不是继续堆题解导入功能，而是把 OI Notebook 从“题解文章管理器”升级为：

> 面向信息学竞赛的训练沉淀系统 + 原子化知识库 + OI 知识图谱 + 复习助手。

## 2. 本轮目标

### 2.1 产品目标

本轮升级需要完成两条主线：

1. **知识库升级**：新增“知识库”主页面，用于组织知识片段、知识集合、知识文章，并展示知识关联、图谱、复习入口。
2. **洛谷导入中心升级**：将原“洛谷导入中心”升级为“训练沉淀中心”，从提交记录/题单/比赛中沉淀知识片段、集合和可选文章。

两者需要共同服务于一个统一目标：

> 让用户的每次训练、每道题、每个 trick、每次复盘都能进入一个可关联、可检索、可视化、可复习的 OI 知识网络。

### 2.2 本轮实现目标

本轮需要优先完成以下事情：

- 新增知识库主入口和主页面。
- 设计并落地三层内容模型：知识片段、知识集合、知识文章。
- 将洛谷导入中心页面化，升级为训练沉淀中心。
- 训练沉淀中心采用三栏布局：来源与批次 / 沉淀工作区 / AI Inspector 预留栏。
- 支持从洛谷提交记录生成更轻量的知识片段和知识集合，而不是默认生成长题解。
- 建立基础知识图谱索引：先基于 frontmatter、显式链接、题号、标签、来源信息建图。
- 支持全局图谱和局部图谱的第一版展示。
- 保留 AI 分析、AI 修改、NoteX 联动、语义抽取等位置，但本轮不真正接入。

### 2.3 本轮非目标

以下内容本轮不做，或者只做占位：

- 不接入新 AI 系统。
- 不实现 NoteX 对训练沉淀内容的真实 patch 修改。
- 不做 embedding 语义相似检索。
- 不做复杂 AI 自动抽取 trick / 错因 / 关联。
- 不做多平台导入，先围绕洛谷。
- 不重做整个 Markdown 编辑器。
- 不强制改造已有所有笔记，只提供兼容和渐进迁移能力。

## 3. 核心概念

### 3.1 内容三层模型

本轮需要将 OI Notebook 的知识内容从单一“题解文章”扩展为三层：

```txt
知识片段 → 知识集合 → 知识文章
```

#### 3.1.1 知识片段

知识片段是最小的人类可读知识单位，适合记录短小、高密度、可复习的信息。

典型内容包括：

- 一道题的核心考点。
- 一个 trick。
- 一个模板细节。
- 一个常见错因。
- 一个算法识别信号。
- 一个代码实现注意点。
- 一段比赛经验。

示例：

```md
---
type: fragment
kind: trick
title: 历史修改可以转成插入历史
topics: [离线处理, 历史版本, 数据结构]
related_problems: [P10633]
created_from: luogu-import
---

当题目统计“任意历史版本中出现过的值”时，很多情况下不需要维护完整版本树，
可以把每次修改看成一次插入，再对所有历史出现值统一统计。
```

#### 3.1.2 知识集合

知识集合是聚合多个题目、片段、文章的内容容器。它不是固定文体，而是一类“训练或专题上下文”。

典型内容包括：

- 今日训练日志。
- 比赛复盘。
- 专题复盘。
- 题单总结。
- 阶段性错题整理。
- 考前复习清单。

示例：

```md
---
type: collection
kind: daily-log
title: 2026-06-28 今日训练
date: 2026-06-28
problems: [P3803, P3375]
topics: [FFT, KMP]
---

今天主要训练了 FFT 和字符串基础。

## 题目记录

- P3803：重点回顾 FFT 的蝴蝶合并。
- P3375：重点回顾 next 数组和 border 的关系。

## 新增片段

- [[蝴蝶合并中 w 和 wlen 的关系]]
- [[border 视角理解 KMP]]
```

#### 3.1.3 知识文章

知识文章是适合连续阅读的完整内容。

典型内容包括：

- 完整题解。
- 算法博客。
- 专题讲义。
- 学习总结。
- 深度复盘。

示例：

```md
---
type: article
kind: algorithm-note
title: 深入理解 FFT 的代码执行过程
topics: [FFT, 单位根, 蝴蝶合并]
related_problems: [P3803]
---

正文自由书写，不强制固定模板。
```

### 3.2 轻结构化原则

本轮必须遵守“轻结构化”原则：

- frontmatter 负责元数据。
- 正文保持自由表达。
- 不强迫每篇内容都有“题意 / 思路 / 错因 / 复杂度 / 代码”。
- 不把所有 AI/机器抽取结果塞进正文。
- 系统可基于 frontmatter 和链接建立索引。
- 机器索引应可重建，不能污染用户长期 Markdown 资产。

## 4. 知识库页面设计

### 4.1 页面定位

知识库不是弹窗，而是 OI Notebook 的主工作区页面。

它的作用是：

- 浏览知识片段、知识集合、知识文章。
- 查看知识图谱。
- 查看当前知识网络的增长状态。
- 查找关联内容。
- 支持阶段复习和考前复习。
- 为未来 AI 抽取、AI 关联、AI 复习规划预留空间。

### 4.2 入口位置

知识库入口建议放在左侧 Activity Bar，和文件、搜索、NoteX、设置同级。

建议结构：

```txt
文件
搜索
知识库
NoteX
设置
```

入口名称建议使用：**知识库**。

不要使用“图谱”作为一级入口名称，因为图谱只是知识库的一个视图。

### 4.3 页面结构

知识库页面采用类似设置页的结构：左侧二级导航 + 右侧主内容。

建议二级导航：

```txt
知识库
- 总览
- 图谱
- 片段
- 集合
- 文章
- 复习
- 错因
- 关联建议
```

### 4.4 总览页

总览页需要有“成果感”，不能做成表单页。

建议展示：

- 知识节点数量。
- 关联数量。
- 本周新增知识片段。
- 最近新增集合。
- 最近新增文章。
- 高频 topic。
- 高频错因。
- 图谱预览。
- 最近训练沉淀。

示例布局：

```txt
知识库总览

本周新增：
- 8 个知识片段
- 2 个知识集合
- 1 篇知识文章

当前知识网络：
- 428 个节点
- 1376 条关联

最近高频主题：
动态规划、数据结构、字符串

[打开知识图谱]
[查看最近沉淀]
[进入复习视图]
```

### 4.5 图谱页

图谱页是本轮重要能力。

第一版至少支持：

- 全局图谱。
- 当前节点局部图谱。
- 按 type / topic / date 过滤。
- 节点点击查看详情。
- 节点跳转到对应 Markdown 内容。

图谱节点类型建议包括：

```txt
problem
algorithm
concept
trick
mistake
template
fragment
collection
article
training
contest
```

第一版不要求所有类型都完整实现，但数据结构应预留。

图谱边类型建议包括：

```txt
links_to
mentions
uses
contains
example_of
related_to
belongs_to
derived_from
prerequisite_of
similar_to
```

第一版重点实现：

- links_to：来自 Markdown 内部链接。
- mentions：来自基础术语匹配或题号匹配。
- belongs_to：来自 frontmatter。
- related_to：来自 frontmatter 的 topics、related_problems。
- derived_from：来自训练沉淀中心生成批次。

### 4.6 片段 / 集合 / 文章视图

每类内容都需要列表视图。

基础能力：

- 按类型筛选。
- 按 topic 筛选。
- 按创建时间排序。
- 按来源筛选。
- 点击打开原 Markdown。
- 显示关联数量。
- 显示所属集合或来源批次。

片段列表应强调信息密度，适合快速复习。

集合列表应强调训练上下文，如日期、题单、比赛、专题。

文章列表继续承接已有 Markdown 文章体验。

### 4.7 复习页

第一版可以先做基础视图，不需要复杂智能推荐。

可支持：

- 最近新增片段。
- 最近 7/30 天沉淀内容。
- 按 topic 查看复习内容。
- 手动标记复习优先级。
- 手动标记掌握状态。

未来 AI 接入后，可扩展为：

- 自动生成考前复习清单。
- 自动发现高频薄弱点。
- 自动按错因聚合。
- 自动生成阶段复习计划。

### 4.8 关联建议页

本轮仅做占位或基础规则建议。

当前可支持：

- 未链接提及：正文出现已有 topic/题号，但没有显式链接。
- frontmatter 缺失提示：已有题号但未写 related_problems。
- 孤立内容提示：没有任何关联的片段/文章。

未来 AI 接入后扩展：

- AI 推荐关联。
- AI 抽取新 trick。
- AI 发现相似内容。
- AI 建议合并/拆分内容。

## 5. 训练沉淀中心设计

### 5.1 页面定位

原“洛谷导入中心”升级为“训练沉淀中心”。

它不再只是把提交导入成文章，而是负责：

> 把洛谷提交、题单、比赛、代码注释等训练材料转化为知识片段、知识集合和可选知识文章。

本轮先围绕洛谷数据源实现，名称上不必强绑定“洛谷”，为未来扩展其他平台预留空间。

### 5.2 页面形态

训练沉淀中心不再使用弹窗，而是主工作区页面。

建议入口：

- 可以在左侧 Activity Bar 中作为“知识库”下的子页面。
- 也可以保留原位置入口，但点击后进入页面式工作区。
- 不建议继续用 modal/dialog 承载。

### 5.3 三栏布局

训练沉淀中心采用三栏布局：

```txt
左栏：来源与批次
中栏：沉淀工作区
右栏：AI Inspector，占位，可收起
```

核心分工：

```txt
左栏管来源。
中栏管操作。
右栏管建议。
```

更具体地说：

- 左栏：决定从哪里来、扫什么、当前批次是什么。
- 中栏：用户真正编辑、选择、确认、写入的主工作区。
- 右栏：展示分析结果、结构化预览、关联建议、未来 AI 修改入口。

### 5.4 左栏：来源与批次

左栏顶部使用切换胶囊选择扫描来源。

建议胶囊：

```txt
[今日] [范围] [题单] [比赛] [单题]
```

不同胶囊展示不同配置。

#### 今日

```txt
今日提交
日期：今天
[扫描今日提交]
```

#### 范围

```txt
时间范围
开始日期：[ ]
结束日期：[ ]
[扫描时间范围]
```

#### 题单

```txt
洛谷题单
题单 ID / 链接：[ ]
[扫描题单提交]
```

#### 比赛

```txt
洛谷比赛
比赛 ID / 链接：[ ]
[扫描比赛提交]
```

#### 单题

```txt
单题补录
题号：[ ]
[扫描单题]
```

扫描按钮应放在左栏来源配置卡片中，因为它与当前来源强绑定。

左栏下方展示最近批次：

```txt
最近批次
- 2026-06-28 今日训练
- DP 专题题单
- 2026-06-25 模拟赛
```

点击批次后，中栏切换到该批次。

### 5.5 中栏：沉淀工作区

中栏是主操作区，不是只读列表。

中栏顶部展示当前批次状态：

```txt
当前批次：2026-06-28 今日训练
扫描到 6 题 · 已整理 3 项 · 待确认 2 项 · 已写入 1 项

[整理选中项] [写入知识库]
```

本轮不接 AI，因此“整理选中项”可以先是规则整理 / 模板生成，不调用 AI。文案上也不要写成“AI 分析”。

列表项采用紧凑卡片形式：

```txt
[ ] P3803 多项式乘法        AC · 18:42
    topics: FFT / 单位根 / 蝴蝶合并
    将生成：题目片段 / 可选文章
    状态：待确认
```

用户在中栏可以直接操作：

- 选择是否沉淀该题。
- 编辑一句话题意。
- 编辑核心考点。
- 编辑 topics。
- 编辑 related_problems。
- 选择输出类型：片段 / 集合 / 文章。
- 修改生成文件名和路径。
- 确认是否写入知识库。
- 跳过某项。

中栏应支持展开单项编辑：

```txt
P3803 多项式乘法

一句话题意：
[给两个多项式，求乘积系数。]

核心考点：
[FFT]

复习提示：
[重点看单位根分治和蝴蝶合并。]

输出：
[x] 题目片段
[ ] 完整文章

关联：
topics: [FFT, 单位根]
related_problems: [P3803]
```

字段不应强制全部填写。用户可以只保留必要字段。

### 5.6 右栏：AI Inspector 预留栏

右栏本轮保留，但不接入 AI。

右栏当前职责：

- 展示当前选中项的原始信息。
- 展示将写入的 frontmatter 预览。
- 展示基础关联预览。
- 展示图谱更新预览。
- 展示未来 AI 功能占位。

右栏当前可显示：

```txt
当前选中：P3803 多项式乘法

原始信息：
- 提交时间
- 提交状态
- 代码摘要
- 注释摘要

写入预览：
- 将生成 fragment
- 将关联 topic: FFT
- 将关联 problem: P3803

图谱更新：
- 新增节点：P3803
- 新增边：P3803 -> FFT

AI 能力升级后将在这里提供：
- 题意压缩
- trick 提炼
- 错因识别
- 关联建议
- NoteX 修改联动
```

右栏应支持收起，类似 Codex Desktop 的右侧辅助栏。

### 5.7 写入知识库

写入时应生成或更新：

- Markdown 文件。
- frontmatter。
- 知识库索引。
- 图谱节点和边。
- 批次记录。

写入后提供反馈：

```txt
已写入知识库：
- 题目片段 5 个
- 训练集合 1 个
- 关联 18 条

[查看生成集合]
[打开知识图谱]
[继续处理批次]
```

## 6. AI 暂缓接入说明

由于当前 AI 功能正在同步升级，本轮知识库和训练沉淀中心不直接接入 AI。

### 6.1 本轮不做

本轮不实现：

- AI 自动提炼题意。
- AI 自动提炼 trick。
- AI 自动识别错因。
- AI 自动生成文章。
- AI 自动修改中栏内容。
- NoteX 对当前卡片的 patch 修改。
- AI embedding 语义相似推荐。

### 6.2 本轮需要预留

虽然不接入 AI，但需要在产品和代码结构上预留：

- 右栏 AI Inspector 区域。
- 当前选中项上下文模型。
- 可被未来 AI 修改的中栏字段模型。
- 生成内容的 patch/diff 接口位置。
- 关联建议数据结构。
- 抽取结果缓存位置。
- NoteX 未来读取当前页面上下文的入口。

### 6.3 未来 AI 接入后的目标形态

未来 AI 接入后，用户可以在 NoteX 中提出：

```txt
把当前选中的 P3803 卡片改短一点，只保留考前复习需要看的内容。
```

系统应支持：

```txt
中栏选中内容
↓
NoteX 获取当前上下文
↓
AI 生成 patch
↓
中栏显示 diff
↓
用户接受 / 拒绝
```

但这不是本轮范围。

## 7. 数据模型建议

### 7.1 Markdown frontmatter

所有用户可见内容继续使用 Markdown + frontmatter。

基础字段建议：

```yaml
type: fragment | collection | article
kind: string
title: string
date: YYYY-MM-DD
topics: string[]
related_problems: string[]
source: luogu | manual | import | unknown
created_from: string
review_priority: low | medium | high
status: draft | active | archived
```

不同类型可扩展字段。

#### fragment 扩展

```yaml
kind: trick | problem-note | mistake | template-note | concept-note
problem_id: string
collection_id: string
```

#### collection 扩展

```yaml
kind: daily-log | problemset-review | contest-review | topic-review
problems: string[]
fragments: string[]
articles: string[]
```

#### article 扩展

```yaml
kind: solution | algorithm-note | topic-note | study-note
related_fragments: string[]
```

### 7.2 内部索引

机器生成索引放在内部目录中，例如 `.oinb/`。

建议结构：

```txt
.oinb/
  graph/
    nodes.json
    edges.json
    aliases.json
    batches.json
    extraction-cache.json
  index/
    markdown-index.json
    search-index.json
```

原则：

- Markdown 是长期资产。
- `.oinb/` 是机器缓存，可重建。
- 不要把所有机器分析结果污染到正文。

### 7.3 图谱节点

节点字段建议：

```json
{
  "id": "problem:P3803",
  "type": "problem",
  "title": "P3803 多项式乘法",
  "source": "luogu",
  "refs": ["notes/fragments/P3803.md"],
  "createdAt": "2026-06-28T00:00:00"
}
```

### 7.4 图谱边

边字段建议：

```json
{
  "from": "problem:P3803",
  "to": "topic:FFT",
  "type": "uses",
  "source": "frontmatter",
  "confidence": 1.0,
  "refs": ["notes/fragments/P3803.md"]
}
```

source 可选值：

```txt
frontmatter
wikilink
term_match
import_rule
manual
ai_extract_future
embedding_future
```

本轮先使用：

```txt
frontmatter
wikilink
term_match
import_rule
manual
```

AI 相关 source 仅预留。

## 8. 关联生成规则

本轮不接 AI，先使用确定性规则建图。

### 8.1 frontmatter 建图

根据 frontmatter 字段建立关系：

- related_problems -> problem 节点。
- topics -> topic/concept/algorithm 节点。
- type/kind -> 内容节点分类。
- collection 中的 problems/fragments/articles -> belongs_to 关系。

### 8.2 显式链接建图

解析 Markdown 中的 `[[...]]` 链接，生成 links_to 关系。

### 8.3 题号识别

识别正文和 frontmatter 中的洛谷题号，如 `P3803`，生成 problem 节点。

### 8.4 术语与别名匹配

维护基础 OI 术语表和别名表。

示例：

```yaml
FFT:
  aliases: [快速傅里叶变换, fast fourier transform]
AC 自动机:
  aliases: [Aho-Corasick, 多模式串匹配]
FHQ Treap:
  aliases: [非旋 Treap]
```

本轮可先做简单匹配，不做复杂 NLP。

### 8.5 孤立内容提示

如果某个内容没有任何 topics、related_problems、wikilink，可在关联建议页提示用户补充。

## 10. UI 风格要求

### 10.1 总体风格

保持 OI Notebook 现有 VS Code / Codex 式专业工具感。

不要直接模仿 Obsidian 皮肤。

需要学习 Obsidian 的：

- 知识组织方式。
- 反向链接逻辑。
- 图谱视图。
- 多视图浏览。
- 本地 Markdown + 元数据思想。

不要照搬的：

- 默认笔记软件外观。
- 过于通用的文件树优先体验。
- 只按文档链接建图的简单模型。

### 10.2 训练沉淀中心视觉要求

- 页面感强，不像弹窗。
- 三栏边界清晰，但不要割裂。
- 中栏是视觉中心。
- 左栏紧凑，扫描按钮自然嵌入来源配置。
- 右栏可收起，弱于中栏但信息清晰。
- 列表项使用紧凑卡片，不用大块空白卡片。
- 状态徽标要清楚：待整理、待确认、已写入、已跳过。

### 10.3 知识库视觉要求

- 首页有成果感。
- 图谱要有视觉吸引力。
- 片段列表要高信息密度。
- 集合列表要突出上下文。
- 复习页要简洁直接。
- 不展示过多内部技术词，如 nodes.json、confidence、embedding 等。

## 11. 兼容性与迁移

### 11.1 兼容已有 Markdown

已有文章不能被破坏。

对于已有 Markdown：

- 没有 type 时，可视为 article 或 legacy-note。
- 可通过用户确认后补充 frontmatter。
- 不强制迁移。

### 11.2 兼容已有洛谷导入结果

旧版导入生成的题解文章应继续可用。

可以在知识库中识别为：

```yaml
type: article
kind: solution
source: luogu-import-legacy
```

### 11.3 渐进升级

用户可以逐步把旧题解拆出片段，但本轮不强制。

未来可提供“从当前文章提取知识片段”的 AI 功能，本轮只预留入口。

### Phase 3：基础图谱索引

## 13. 验收标准总览

本轮完成后，应该达到以下效果：

1. 用户可以从主界面进入“知识库”。
2. 用户可以看到知识库总览、图谱、片段、集合、文章等页面。
3. 原洛谷导入中心不再以弹窗为主，而是升级为页面式训练沉淀中心。
4. 训练沉淀中心有清晰三栏：来源与批次、沉淀工作区、AI Inspector 预留栏。
5. 扫描按钮位于左栏来源配置中，和当前来源模式绑定。
6. 中栏支持用户直接编辑和确认沉淀内容。
7. 右栏显示预览和建议，但本轮不调用 AI。
8. 用户可以从提交记录生成知识片段和知识集合。
9. 用户可以选择是否生成完整文章。
10. 生成内容使用 Markdown + frontmatter。
11. 知识图谱能基于 frontmatter、wikilink、题号、基础术语建立节点和关系。
12. 图谱页能展示全局和局部关系。
13. 所有 AI 功能位置预留，但不会依赖 AI 才能使用。
14. 已有 Markdown 和旧导入内容不被破坏。

## 14. 一句话总结

本轮升级要把 OI Notebook 从“题解导入和 Markdown 管理”推进到“训练沉淀和知识网络”：训练沉淀中心负责把洛谷提交、题单、比赛转化为知识片段、知识集合和可选文章；知识库负责把这些内容通过 frontmatter、链接、基础规则和图谱索引组织成可关联、可复习、可视化的 OI 知识系统。AI 能力本轮只预留，不接入，等待 AI 系统升级完成后再作为增强层加入。
