# OI Notebook UI Pass 规划

## 1. 背景

OI Notebook 目前已经具备比较完整的核心能力：

- 本地 Markdown 笔记管理
- 双栏编辑与实时预览
- Local Blog v2 本地博客预览
- 洛谷提交扫描、规则筛选、生成预览、确认写入
- AI Prompt / AI 辅助整理
- Git 同步等进阶能力
- 洛谷风格 Markdown 渲染能力，包括 callout、代码块增强、cute-table、表格合并等

现在的问题不再是“能不能用”，而是“第一眼看起来是否像一个可以长期使用的正式桌面软件”。

当前 UI 仍有明显的开发中工具感：

- 黑色过重，层次主要靠硬边框和按钮堆出来。
- 顶部入口仍然有功能清单感。
- 设置入口已经改成齿轮，但还没有成为正式设置中心。
- 左侧文件树更像文件列表，还不像稳定的笔记导航。
- 欢迎页已经补了 onboarding，但日常工作台属性还不够。
- 编辑器区域结构已经变清楚，但 toolbar、文章信息、预览样式还需要继续 polish。

本轮 UI pass 的目标不是局部美化，而是把 OI Notebook 从“功能集合”升级成“专业工作台”。

核心方向：

```text
像 VS Code 一样克制、稳定、专业；
像洛谷编辑器一样清楚、顺手；
但不要做成网页后台管理系统。
```

## 2. 产品定位

OI Notebook 不应该只是普通 Markdown 编辑器，也不应该只是洛谷同步工具。

更准确的定位是：

> 面向 OI 学习者的本地题解、trick、复盘、洛谷提交与 AI 辅助整理工作台。

UI 应该突出：

- 长期写作
- 稳定整理
- 快速复盘
- 可控导入
- 本地优先
- AI 辅助但不强迫

这意味着主界面应该服务“写笔记”和“继续工作”，而不是把所有功能一次性展示出来。

## 3. 当前已完成的 UI / Markdown 基础

本规划不从零开始。以下内容已经完成或基本完成，后续只需要 polish，不要重复实现。

### 3.1 Markdown 能力

已经完成：

- 洛谷风格 callout：`info / success / warning / error`
- callout 折叠与 `{open}` 默认展开
- 代码块无语言默认 C++
- `lines=5-6,11` 行高亮
- 显式开启行号：`showLineNumbers / line-numbers / lineNumbers`
- `align`
- `epigraph`
- `cute-table{three}`
- `cute-table{tuack}`
- `cute-table{tuack=3}`
- `^` 纵向合并
- `>` 横向合并
- 桌面预览与 Local Blog v2 尽量保持一致

暂不做：

- `<` 横向合并

原因：`<` 的实际收益较低，但和 `>`、`^` 混用时容易产生复杂歧义。当前 `^` 和 `>` 已覆盖大多数 OI 表格写作场景。

### 3.2 洛谷导入

已经完成：

- 扫描范围可控：按条数或时间范围
- 只读扫描提交列表
- 导入规则：只处理 AC、同题最新 AC、无 insight 时跳过或生成源码草稿
- 生成预览后再写入
- 预览包含渲染预览、Markdown 源文、提交源码
- 同步位置 `last_submission_id` 可查看、编辑、清空
- 支持跳过选中、全选可候选、取消全选

后续主要做 UI polish，不优先继续加功能。

### 3.3 编辑器结构

已经完成：

- raw frontmatter 从正文编辑区隐藏
- `文章信息` 折叠区取代 `FRONTMATTER`
- 共享 Markdown toolbar 横跨编辑与预览区域
- 双栏 / 仅编辑 / 仅预览模式
- 常用 Markdown 快捷键
- MarkdownPreview 首次渲染性能做过一刀优化

后续主要做 toolbar 视觉 polish、文章信息区域 polish、预览样式统一。

### 3.4 顶部栏第一刀

已经完成：

- 去掉 `主操作 / 核心能力 / 更多`
- `更多` 改成齿轮设置入口
- 低频工具初步收纳到设置与工具对话框

后续需要做真正设置中心，并继续给顶部栏减负。

### 3.5 欢迎页

已经完成：

- 未选中文件时欢迎页占据中右完整工作区
- 不再和预览栏分裂
- onboarding 已介绍 Markdown、洛谷、AI、Local Blog 等能力

后续应从“功能介绍页”逐步改为“工作台 Dashboard”。

## 4. 第一轮 UI Pass 目标

第一轮 UI pass 不追求一次性完成所有理想设计，而是解决最影响第一印象和长期使用感的问题。

第一轮目标：

1. 统一暗色主题基准，解决“太黑、不统一、不高级”。
2. 建立正式设置中心，解决“设置入口临时感”。
3. 增加底部状态栏，承接保存、Blog、AI、Luogu、Git、缩放等状态。
4. 进一步精简顶部栏，让它不再像功能清单。
5. polish 左侧文件树，让它更像笔记导航。
6. polish 编辑器 toolbar，降低按钮噪音。
7. 把欢迎页从 onboarding 逐步改为 Dashboard。
8. 对洛谷导入中心做流程视觉 polish。

第一轮不做：

- 完整 Activity Bar
- 完整浅色主题
- 大规模重构主布局
- 一次性改完整个 UI
- 打包发布

## 5. 设计原则

### 5.1 主编辑体验优先

用户打开软件后，最重要的是：

- 找到笔记
- 写 Markdown
- 看预览
- 整理洛谷提交
- 用 AI 辅助复盘

外围功能都应该服务编辑体验，而不是抢占主界面注意力。

### 5.2 顶层入口必须克制

顶部栏不应该承载所有功能。

顶部栏应只负责：

- 产品身份
- 当前笔记 / 当前工作区
- 保存状态
- 少量高频入口
- 设置齿轮

低频工具应进入设置中心、工具页或状态栏。

### 5.3 设置和工具要分层

设置是长期配置，工具是立即执行动作。

例如：

| 类型 | 示例 |
|---|---|
| 设置 | API Key、主题、字体、数据目录、默认视图 |
| 工具 | 测试连接、重启博客、同步 Git、打开目录 |

它们可以在同一个设置中心里出现，但必须在结构上区分，不要都变成同等重量的按钮。

### 5.4 不做网页后台管理风

OI Notebook 应该像 IDE / 编辑器，而不是 SaaS 控制台。

避免：

- 大量卡片堆叠
- 大标题堆页面
- 过多主按钮
- 过强边框和阴影
- 炫酷但无意义的动效

追求：

- 克制
- 稳定
- 清楚
- 低噪音
- 长时间使用不累

### 5.5 先建立设计系统，再局部 polish

颜色、字体、边框、hover、active 状态应通过统一 token 控制。

不要继续每个组件单独手搓颜色。

## 6. 总体布局方向

长期方向接近：

```text
┌────────────────────────────────────────────────────────────┐
│ OI Notebook    当前文件 / 保存状态              设置 / 状态 │
├────────────────────────────────────────────────────────────┤
│ 文件树                 │ 编辑器 / 预览工作区              │
│ 搜索 / 新建            │ Markdown toolbar                 │
│ tricks                 │ 文章信息                         │
│ problems               │ 编辑器              Preview      │
│ luogu                  │                                  │
│ inbox                  │                                  │
├────────────────────────────────────────────────────────────┤
│ 已保存 | Blog 运行中 | AI: DeepSeek | Luogu 已登录 | 120% │
└────────────────────────────────────────────────────────────┘
```

第一轮不强行做 Activity Bar。当前左侧文件树继续保留，但为未来 Activity Bar 留方向。

## 7. 视觉方向

### 7.1 暗色主题

从纯黑工具感改成接近 VS Code dark 的深灰层级。

建议建立 theme tokens：

| Token | 用途 | 建议感觉 |
|---|---|---|
| `app-bg` | 最外层背景 | 深灰黑，不要纯黑 |
| `titlebar-bg` | 顶栏背景 | 比编辑区略深 |
| `sidebar-bg` | 左侧文件树 | 比编辑区略深 |
| `editor-bg` | 编辑器区域 | 接近 VS Code editor background |
| `panel-bg` | 卡片 / 面板 / 弹窗 | 比背景稍亮 |
| `hover-bg` | hover 状态 | 低对比浅灰 |
| `active-bg` | 选中状态 | 明确但不刺眼 |
| `border-subtle` | 分割线 | 低对比 |
| `text-main` | 主文字 | 不用纯白 |
| `text-muted` | 次级文字 | 降低权重 |
| `accent` | 强调色 | 少量使用 |

第一刀主题 pass 只做颜色和层级，不改布局。

### 7.2 字体

不要全局使用等宽字体。

建议：

| 区域 | 字体 |
|---|---|
| UI、按钮、设置、侧栏 | 系统 sans-serif |
| Markdown 编辑器 | monospace |
| 代码块 | monospace |
| 预览正文 | sans-serif，后续可配置 |
| 文件路径、技术状态 | 可使用 monospace，但要克制 |

之前字体/字号尝试过但没有满意。后续要做时，应作为独立一刀处理，不要混入 theme token pass。

### 7.3 边框和阴影

暗色界面不要依赖强边框和重阴影。

原则：

- 分割线低对比。
- 面板靠背景层级区分。
- 弹窗可以有轻微边框和背景遮罩。
- 不要到处都是发亮边框。
- 不要使用廉价毛玻璃或过强渐变。

## 8. 顶部栏规划

### 8.1 顶部栏职责

顶部栏只负责：

- 产品名
- 当前文件 / 当前路径
- 保存状态
- 少量高频入口
- 设置齿轮

### 8.2 当前保留入口

第一轮可以保留：

- 新建
- 打开博客
- 洛谷
- AI
- 设置齿轮

但不要都做成高权重大按钮。后续状态栏完成后，应继续减少顶部信息量。

### 8.3 应移出顶部栏的入口

以下入口不应长期占据顶部栏：

- 测试连接
- 重启博客
- 同步 Git
- AI Prompt
- 笔记文件夹
- 低频配置项

它们应进入：

- 设置中心
- 工具页
- 状态栏
- 后续命令面板

## 9. 设置中心规划

### 9.1 目标

把当前齿轮入口从“小工具弹窗”升级为正式设置中心。

第一版设置中心重点是建立结构，不要求所有设置都真正持久化。

### 9.2 建议结构

```text
设置

左侧分类：
常规
外观
编辑器
Markdown
AI
洛谷
博客
Git
数据与存储
关于

右侧：
对应设置项、状态、说明、操作按钮
```

### 9.3 分类内容

| 分类 | 内容 |
|---|---|
| 常规 | 启动行为、默认工作区、基础说明 |
| 外观 | 主题、字体、缩放、紧凑模式 |
| 编辑器 | 双栏模式、滚动同步、自动保存、编辑器字体 |
| Markdown | 洛谷语法、KaTeX、代码高亮、表格增强 |
| AI | Provider、Base URL、API Key、模型、AI Prompt、测试连接 |
| 洛谷 | Cookie、登录状态、导入中心、导入规则、同步位置 |
| 博客 | 打开博客、重启博客、端口状态 |
| Git | 同步 Git、自动提交说明、进阶警告 |
| 数据与存储 | notes 路径、配置路径、缓存路径、打开目录 |
| 关于 | 产品定位、preview 状态、版本信息 |

### 9.4 第一版要求

第一版只需要做到：

- 宽屏 modal
- 左侧分类
- 右侧内容
- 原有功能入口不丢
- 设置和工具动作分层
- 状态说明更清楚

不要在第一版里强行实现主题持久化、字体持久化、窗口大小设置等功能。可以先预留位置。

### 9.5 UI 回归注意事项

- 复杂设置中心 / 宽屏 modal 不能沿用默认小 Dialog 宽度。
- 需要显式设置宽度、高度、左右栏宽度和内部滚动。
- 宽屏 modal 不仅要显式设置宽度，还要显式处理 header / body / footer 布局。
- body 区域必须使用 `min-h-0` 和内部滚动，footer 不能覆盖内容。
- 验收时要检查底部分类、说明和按钮是否互相重叠。
- 验收时必须检查中文说明是否正常横向阅读，不能被挤成竖排。
- 不要让复杂功能页看起来像被默认弹窗尺寸压坏。

## 10. 状态栏规划

状态栏建议提前进入第一轮 UI pass。

原因：它可以承接大量当前挤在顶部栏的信息，让顶部更干净。

状态栏可以显示：

```text
已保存
Blog 运行中
AI: DeepSeek
Luogu 已登录
Git 状态
Markdown
UTF-8
行列
缩放比例
```

第一版状态栏不需要所有数据都精确接入，可以先接入已有状态：

- 保存状态
- Blog 状态
- AI 是否配置
- Luogu 是否配置
- 当前缩放比例
- Git 同步入口或状态

要求：

- 不挤占编辑区。
- 视觉低调。
- 点击部分状态可以打开对应设置。
- 不要让状态栏变成第二个工具栏。

## 11. 左侧文件树规划

### 11.1 目标

从“文件列表”升级为“笔记导航”。

建议结构：

```text
顶部：
搜索 / 新建

中间：
目录树

底部：
notes 根目录 / 刷新 / 打开文件夹
```

### 11.2 视觉原则

- 文件名是主信息。
- 时间信息弱化，不要抢视觉。
- 文件夹和笔记的 icon 统一。
- hover、active、selected 状态统一。
- 缩进要清楚。
- 列表密度适合长时间浏览。

### 11.3 暂不做完整 Activity Bar

Activity Bar 是长期方向，但第一轮不强行做。

理由：

- 当前主布局已经有左侧文件树。
- 直接加 Activity Bar 会牵动主结构。
- 现在更重要的是把现有文件树 polish 成稳定导航。

## 12. 编辑器区域规划

### 12.1 保留当前结构

当前编辑器区域方向是对的：

```text
共享 Markdown toolbar
文章信息
编辑器 / 预览
```

不要推倒重来。

### 12.2 Toolbar

当前 toolbar 问题是功能密度偏高，基础格式和高级语法混在一起。

后续建议：

高频按钮直接显示：

```text
加粗
斜体
删除线
行内代码
链接
图片
引用
代码块
表格
```

低频或高级能力进入“插入”菜单：

```text
数学公式
Callout
题目模板
题解模板
cute-table
align
epigraph
表格合并
```

目标：

- 降低按钮噪音。
- 让图标和文字风格统一。
- 不影响现有快捷键。
- 不丢现有插入能力。

### 12.3 文章信息区域

“文章信息”应做成正式折叠面板。

建议：

- 默认折叠。
- 展开后编辑 frontmatter / 标题 / 标签 / 分类。
- 面板样式与编辑器统一。
- 不像残留表单。
- 和隐藏 raw frontmatter 的功能保持一致。

### 12.4 编辑 / 预览切换

保留在 toolbar 右侧，但视觉应更轻。

当前模式：

```text
双栏 | 仅编辑 | 仅预览
```

后续可以进一步 polish：

- 改成 segmented control
- 降低按钮边框
- 与缩放、滚动同步等视图设置归在一起

### 12.5 预览样式

预览区需要降噪。

建议：

- 标题层级清楚但不过大。
- 正文不使用纯白。
- 表格边框降低对比。
- 表头背景弱化。
- 代码块、引用、callout 使用统一面板背景。
- 行高更适合阅读。
- 预览像博客文章，而不是调试页面。

## 13. 首页 / 欢迎页规划

### 13.1 当前状态

欢迎页已经从半栏旧空状态修成全宽 onboarding，能介绍 Markdown、洛谷、AI、Local Blog 等能力。

### 13.2 下一步目标

从“功能说明页”升级为“Dashboard”。

日常首页应该优先帮助用户继续工作，而不是反复介绍功能。

建议结构：

```text
欢迎回来

继续编辑
- 最近笔记 1
- 最近笔记 2
- 最近笔记 3

快速操作
- 新建笔记
- 从洛谷导入
- 打开本地博客
- 配置 AI

当前状态
- Blog：运行中 / 未运行
- AI：已配置 / 未配置
- 洛谷：已登录 / 未配置
- notes：当前路径
```

### 13.3 首次使用和日常使用分离

不要简单删除 onboarding。

建议：

- 首次使用或空 notes 时显示引导。
- 已有笔记后显示 Dashboard。
- Dashboard 里保留轻量帮助入口。

## 14. 洛谷导入中心规划

### 14.1 当前状态

洛谷导入已经从黑盒同步变成可控工作流。

已有流程：

```text
扫描提交
选择提交
生成预览
审阅内容
写入笔记
管理同步位置
```

### 14.2 后续 UI polish

未来可以产品化为明确 stepper：

```text
1. 扫描
2. 选择
3. 生成
4. 审阅
5. 写入
```

建议组件：

- Stepper
- 当前登录状态
- 导入范围设置
- 请求间隔说明
- 生成预览状态
- 写入前确认
- 导入结果摘要

### 14.3 当前优先级

洛谷导入中心功能已经可用，不是第一轮 UI pass 的最先项。

但它需要有正式入口，不要继续像临时工具藏在菜单里。

## 15. 数据与机房环境

OI Notebook 需要考虑学校机房环境：

- 默认窗口不能太小。
- 三栏布局初始不能挤。
- notes 数据位置要清楚。
- 配置文件和缓存位置要可解释。
- 同学不应被要求运行 Node / pnpm。
- AI / 洛谷状态要可见，但不要吓人。

后续需要单独处理：

- 默认窗口大小
- 数据目录说明
- 打包发布流程
- 同学 preview 使用说明

在你明确同意之前，不做打包发布。

## 16. 第一轮实施顺序

每一步都必须独立验收、独立提交。

## 17. 每一步验收标准

### 17.1 UI 审计

验收标准：

- 不改文件。
- 输出当前主要 UI 区域清单。
- 标明每个区域的问题、建议和影响文件。
- 给出后续拆分任务建议。
- 不泛泛写设计口号。

### 17.2 Theme tokens

验收标准：

- 颜色集中到统一 token。
- 大面积纯黑减少。
- 边框、hover、active、文字颜色统一。
- 不改变功能逻辑。
- 深色主题更接近 VS Code dark。

### 17.3 设置中心

验收标准：

- 点击齿轮进入宽屏设置中心。
- 左侧有分类。
- 右侧有对应内容。
- AI、洛谷、博客、Git、数据目录等入口被合理收纳。
- 原有功能入口不丢失。

### 17.4 状态栏

验收标准：

- 底部出现稳定状态栏。
- 能显示保存、Blog、AI、Luogu 等核心状态。
- 视觉低调，不变成第二个工具栏。
- 不挤占编辑区。
- 顶部栏因此可以继续减负。

### 17.5 顶部栏

验收标准：

- 顶部按钮明显减少。
- 顶部不再像功能清单。
- 当前文件、保存状态清楚。
- 低频工具迁移到设置中心或状态栏。

### 17.6 左侧文件树

验收标准：

- 文件夹、文件、选中态、hover 态统一。
- 文件名层级高于时间信息。
- 搜索和新建入口更自然。
- 视觉更接近笔记导航。

### 17.7 编辑器 toolbar

验收标准：

- 高频按钮保留。
- 低频按钮进入菜单。
- 视觉分组更轻。
- 双栏 / 仅编辑 / 仅预览切换清楚。
- 不影响现有 Markdown 插入能力和快捷键。

### 17.8 首页 Dashboard

验收标准：

- 首页优先展示继续编辑、快速操作和当前状态。
- 功能说明弱化。
- 首次使用引导和日常首页区分。
- 新用户不会迷路，老用户不会被说明文档打扰。

### 17.9 洛谷导入中心 polish

验收标准：

- 用户能明确知道当前处于扫描、选择、生成、审阅、写入哪一步。
- 重要危险动作有说明。
- 规则、同步位置、预览结果层级清楚。
- 不改变已有导入逻辑。

## 18. Codex 推进原则

每次只给 Codex 一个明确任务，不允许自由发挥大改。

通用规则：

- 小任务只看 AGENTS.md、过滤后的 git status 和直接相关文件。
- 不通读 PROJECT.md、docs/HANDOFF.md、docs/OI-Notebook-PRD-v1.md，除非任务明确需要。
- 使用 `git status --short -- . ":(exclude)notes/**"`。
- 不处理 `notes/**`。
- 不使用 `git add .`。
- 提交前精确 `git add -- <paths>`。
- 提交前检查 `git diff --cached --name-only`。
- 不打包发布，除非用户明确说可以。

建议第一步 Codex 任务：

```text
只读审计当前 UI，不改代码。

请阅读 AGENTS.md、过滤后的 git status、src/App.tsx、src/index.css，以及与 UI 布局直接相关的主要组件。

输出一份当前 UI 审计报告，包括：

1. 当前主界面结构
2. 顶部栏问题
3. 左侧文件树问题
4. 欢迎页 / Dashboard 问题
5. 编辑器区域问题
6. 设置入口问题
7. 当前颜色、字体、边框、hover、active 状态的问题
8. 建议的 UI 改造顺序
9. 每一步预计会改哪些文件
10. 哪些地方不能动业务逻辑

要求：
- 不修改任何文件。
- 不新增依赖。
- 不动 notes/**。
- 不打包发布。
```

第二步再做 theme token，不直接改设置中心和布局大结构。

## 19. 非目标

第一轮 UI pass 不做：

- 完整浅色主题
- 完整 Activity Bar
- 完整命令面板
- 一次性重构所有页面
- 炫酷动效
- 毛玻璃大改
- 发布打包

这些可以后续讨论，不进入当前第一轮硬范围。

## 20. 总结

本轮 UI 大改的核心不是“更好看”，而是重新建立产品结构。

第一轮最重要的交付：

- 暗色主题统一
- 设置中心正式化
- 状态栏建立
- 顶部栏减负
- 文件树变成笔记导航
- 编辑器 toolbar 降噪
- 首页从 onboarding 走向 Dashboard

最终目标是让用户第一眼感觉：

> 这是一个可以长期用来整理 OI 题解、trick、复盘、洛谷提交和 AI 辅助内容的专业桌面工作台。
