# P6329 震波 点分树笔记

P6329 震波是点分树比较经典的题。题目要支持点权修改，以及查询距离某个点不超过 `k` 的点权和。

直接每次 DFS 找距离不超过 `k` 的点会 TLE。点分树的作用是把“所有会影响当前点答案的点”拆到若干重心祖先上维护。

核心想法：

对一个查询点 `u`，沿点分树父亲一路向上枚举重心 `x`。

如果原树距离 `d = dist(u, x)`，那么所有满足 `dist(v, x) <= k - d` 的点 `v` 都可能贡献到答案。

因此每个点分树重心 `x` 维护一个按距离统计的结构，比如 Fenwick 或 vector 前缀和：

- `all[x]`：所有点到重心 `x` 的距离分布贡献。
- `sub[x]`：某个点分树儿子方向的贡献，用来容斥，避免重复计算。

查询时：

    ans += query(all[x], k - dist(u, x));
    ans -= query(sub[child], k - dist(u, x));

修改点权时：

    delta = new_value - old_value;

    for (int x = u; x; x = pa[x])
    {
        update(all[x], dist(u, x), delta);

        if (pa_child_exists)
            update(sub[child], dist(u, pa[x]), delta);
    }

这里最容易错的是 `sub` 的归属。

`sub` 不是随便扣，它表示“从当前点 `u` 往上走到某个重心父亲时，`u` 所在的那个点分树子块对父亲的贡献”。如果 child 关系记错，答案会重复或少算。

另一个常见坑是距离数组。

如果每次查询都临时 LCA 计算距离，可以写得简单，但常数略大。也可以在建点分树时预处理每个点到各层重心的距离，查询更快，但实现更复杂。

P6329 这类题最值得检查：

1. 点分树父亲 `pa` 是否建对。
2. `dist(u, x)` 是否是原树距离。
3. 修改时是否更新了所有点分树祖先。
4. 查询时是否正确扣除了子块贡献。
5. Fenwick / vector 下标是否从 0 或 1 统一。
6. `k - d < 0` 时必须跳过。
7. 修改点权时要用差值 `delta`，不能直接覆盖。

这题调试时可以先暴力对拍小数据。

如果答案总是偏大，大概率是容斥没扣；如果答案总是偏小，大概率是扣错了方向或更新漏了某层祖先。
