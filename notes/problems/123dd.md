# 点分树模板结构

点分树可以理解成把原树不断找重心，得到的一棵“重心父子关系树”。它不是原树的替代品，而是用来加速动态树上查询的辅助结构。

常见数组：

- `sz[u]`：当前分治连通块中，以 `u` 为根的子树大小。
- `vis[u]`：点 `u` 是否已经被选为某一层的重心。
- `pa[u]`：点分树上 `u` 的父亲，也就是上一层重心。
- `dep[u]`：原树深度，通常给 LCA 用。
- `fa[u][k]`：原树倍增父亲，用来算 LCA。
- `dis(u, v)`：原树上两个点的距离。

模板流程大概是：

1. 在当前连通块内求大小。
2. 找当前连通块重心。
3. 把重心标记为已使用。
4. 对重心相邻的每个未使用连通块继续递归。
5. 把递归得到的子重心父亲设为当前重心。

伪代码结构如下：

    void build(int u, int p)
    {
        sum = get_size(u, 0);
        rt = 0;
        get_root(u, 0);
        int c = rt;

        vis[c] = true;
        pa[c] = p;

        for (int v : g[c])
        {
            if (vis[v]) continue;
            build(v, c);
        }
    }

这里有一个细节：`build(v, c)` 里的 `v` 只是当前剩余连通块的入口，不一定是子树根意义上的父子关系。原树是无根树，点分治每一层处理的是一个被删重心后形成的连通块。

点分树查询时，一般不是 DFS，而是沿 `pa[u]` 向上跳：

    for (int x = u; x; x = pa[x])
    {
        int d = dist(u, x);
        // 用 x 维护的信息更新答案
    }

因为点分树高度通常是 `O(log n)`，所以每次修改 / 查询只会访问 `O(log n)` 个重心祖先。

点分树最适合解决的问题：

- 动态修改点颜色，查询最近黑点。
- 动态点权修改，查询距离相关统计。
- 带距离限制的树上统计。
- 多次询问树上某类点到当前点的贡献。

它不适合用来替代所有树上算法。如果只是静态路径查询，LCA、树剖、DSU on tree 可能更简单。
