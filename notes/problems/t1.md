# OI Notebook 修复任务：重构 `/题解格式化` 的保护区和规则顺序，修复误伤小数、文件名、C++、复杂度和列表的问题

## 当前实测问题

用户用一篇漏洞百出的题解测试后，发现 formatter 仍有严重误伤。当前效果不能提交。

具体问题如下：

1. 小数被破坏
   `3.14` 被格式化成了 `$3$。14`，这是严重错误。

2. 文件名被破坏
   `std.cpp` 被格式化成了 `std。cpp`，这是严重错误。

3. 路径 / 版本号被破坏
   `v1.2.3` 被格式化成了 `v1.2.$3$`，这是严重错误。

4. C++ 被误公式化
   `C++` 被格式化成了 `$C$++`，这是严重错误。
   `C++STL` 应该更接近 `C++ STL`，不能拆成公式。

5. 有序列表被中文标点规则破坏
   `1.第一条` 被格式化成 `1。第一条`，破坏了 Markdown 有序列表。

6. 复杂度表达被拆坏
   `O(logm)` 被格式化成 `$O$(logm)`。
   `O((n+m)logm)` 被格式化成 `$O$((n+m)logm)`。
   正确方向应是整体识别为公式，例如 `$O(\log m)$` 或至少 `$O(logm)$`，不能拆成 `$O$(`。

7. 数据范围只处理一半
   `1<=n<=10^5,1<=m<=2*10^5,0<=w<=10^9` 被处理成 `$1 \le n \le 10$^5,1<=m<=2*10^5,0<=w<=10^9`，这明显错误。
   应整体处理每个约束，例如 `$1 \le n \le 10^5$`、`$1 \le m \le 2 \times 10^5$`、`$0 \le w \le 10^9$`。

8. 普通文本里的非数学表达被误转
   `普通文本里的cnt<=n如果不是数学公式` 被转成了 `$cnt \le n$`，这不应该。
   只有明显数学语境或已经在公式里的表达才做 LaTeX 化。

9. 表格内公式没处理
   表格单元格里的 `$a<=b$`、`$f_i->f_{i+1}$` 仍没转换。
   表格结构要保护，但表格单元格普通文本和公式应能格式化。

10. 块级公式没处理
    块级公式里的 `1<=i<=n` 没有变成 `1 \le i \le n`。

11. 引用块格式没处理
    `>这里` 没变成 `> 这里`。可以新增引用标记空格规则。

12. 链接显示文本没格式化
    链接 URL 需要保护，但链接显示文本可以格式化。
    例如 `[洛谷P0000,这个URL不要被破坏](...)` 应至少可以变成 `[洛谷 P0000，这个 URL 不要被破坏](...)`，URL 不变。

## 本轮核心目标

重构 `src/lib/solutionFormatter.ts` 的规则顺序和保护区逻辑。

不要继续在旧 regex 上小修补。当前问题说明规则顺序不够严谨。

推荐处理顺序：

1. 先分离 fenced code block，完整保护代码块内部，只允许改 fence info string 的语言名。
2. 分离 block math，例如 `$$...$$`，对其内部执行数学符号规范，但不要让普通文本规则碰它。
3. 分离 inline code，完整保护。
4. 分离 Markdown 链接和图片：

   * URL / 图片 URL 必须保护
   * 链接显示文本可以后续格式化
5. 分离纯 URL。
6. 分离文件名、路径、版本号、小数等保护 token。
7. 再对普通文本执行：

   * 标题标记空格
   * 引用标记空格
   * 列表标记空格
   * 中文标点
   * 中英文空格
   * 行内公式包装
8. 最后还原保护区。
9. 再做统一收尾，清理多余空格和空行。

## 必须新增或修复的保护规则

### 1. 小数保护

这些不能被拆：

* `3.14`
* `1.2`
* `4e18`
* `1e9`
* `10^5` 如果属于数学约束，应整体进入公式，而不是拆成 `$10$^5`

### 2. 文件名和路径保护

这些不能被中文标点和公式化破坏：

* `std.cpp`
* `main.cpp`
* `a/b/c.cpp`
* `C:\Users\test\a.cpp`
* `.md`
* `.txt`
* `.in`
* `.out`

### 3. 版本号保护

这些不能被拆：

* `v1.2.3`
* `1.2.3`

### 4. C++ / STL / 常见技术词保护

这些不能被包成公式：

* `C++`
* `C++STL`
* `STL`
* `Dijkstra`
* `priority_queue`
* `vector`
* `long long`
* `int`
* `INF`
* `std`

其中 `C++STL` 可以格式化成 `C++ STL`，但不能变成 `$C$++STL`。

### 5. Markdown 列表保护

不能把有序列表里的 `1.` 转成 `1。`。

需要支持：

* `1.第一条` -> `1. 第一条`
* `2. 第二条` 保持合理
* `-第一条` -> `- 第一条`
* `*第三条` -> `* 第三条`

不要破坏普通句子中的数字和句号。

## 数学规则需要增强

### 1. 数据范围整体识别

应支持把明显数据范围变成公式：

输入：

`数据范围满足1<=n<=10^5,1<=m<=2*10^5,0<=w<=10^9.`

期望至少输出类似：

`数据范围满足 $1 \le n \le 10^5$，$1 \le m \le 2 \times 10^5$，$0 \le w \le 10^9$。`

要求：

* 不要出现 `$1 \le n \le 10$^5`
* 不要漏掉后面的 `1<=m`
* `*` 在数学公式中可以转 `\times`

### 2. 复杂度整体识别

应支持：

* `O(logm)` -> `$O(\log m)$` 或 `$O(logm)$`
* `O((n+m)logm)` -> `$O((n+m)\log m)$` 或 `$O((n+m)logm)$`
* `O(n+m)` -> `$O(n+m)$`

关键是不允许出现：

* `$O$(logm)`
* `$O$((n+m)logm)`

### 3. 已有公式继续处理

已有行内公式和块级公式内部都应处理：

* `$a<=b$` -> `$a \le b$`
* `$f_i->f_{i+1}$` -> `$f_i \to f_{i+1}$`
* `$$ 1<=i<=n $$` -> `1 \le i \le n`

### 4. 普通文本箭头和比较符谨慎处理

普通文本里的：

* `a->b`
* `cnt<=n`

如果不是明显数学语境，不要强行转 LaTeX。

但是类似：

* `出边 u->v`
* `状态 f_i->f_{i+1}`
* `1 <= i <= n`

可以按数学表达处理。

这里宁可保守一点，也不要误伤普通文本。

## 新增或修复 Markdown 结构规则

### 1. 标题空格

保持：

* `##题意` -> `## 题意`

### 2. 引用空格

新增：

* `>这里` -> `> 这里`
* `>第二行` -> `> 第二行`

### 3. 列表空格

新增或修复：

* `-第一条` -> `- 第一条`
* `*第三条` -> `* 第三条`
* `1.第一条` -> `1. 第一条`

不要让中文标点规则把 `1.` 变成 `1。`。

## 表格处理要求

表格结构必须保持：

* `| --- | --- |` 不变
* 不在表格行之间插空行
* 不破坏列数量

但表格单元格内容可以格式化：

* `$a<=b$` -> `$a \le b$`
* `Dijkstra算法` -> `Dijkstra 算法`
* `dis_i` -> `$dis_i$`
* inline code 内部仍保护

## 链接和图片处理要求

Markdown 链接：

`[洛谷P0000,这个URL不要被破坏](https://www.luogu.com.cn/problem/P0000?name=a.b&list=1,2,3)`

要求：

* URL 完全不变
* 链接显示文本可以格式化，例如 `洛谷 P0000，这个 URL 不要被破坏`

图片：

`![测试图片,这个URL也不要被破坏](https://example.com/a,b.c.png)`

要求：

* 图片 URL 完全不变
* alt 文本可以格式化，但不要求强制
